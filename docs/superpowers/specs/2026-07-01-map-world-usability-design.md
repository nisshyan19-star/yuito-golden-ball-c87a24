# 第2弾「ワールドマップ化／あそびやすさ強化」設計書

> 対象: サッカーRPG「ユイトと黄金のサッカーボール」（単一 index.html・オフライン・9歳向け）
> 作成: 2026-07-01
> ステータス: 設計承認済み（げんちゃん 2026-07-01 OK）→ 実装計画へ

## ゴール（一文）

27マップを画面切替式のまま維持しつつ、「今どこ？どっちへ行く？全体像は？」の不安を消す**5つのあそびやすさ機能**を、既存処理を壊さず上乗せする。

## 背景・現状把握（コード実測）

- 画面サイズ **VW=288px（=9タイル分）× VH=512px（=16タイル分）**、タイル **TS=32px**（`src/engine/canvas.js`, `src/scenes/field-scene.js:1643`）。
- 標準マップは16タイル幅×18タイル高＝512×576pxで画面より大きいため、**カメラ追従（プレイヤー中央・端クランプ）は全マップで既に稼働**している（`clampCamera` `field-scene.js:197`、draw内 `field-scene.js:2303-2304`）。
- ただし移動は `px = nx; py = ny;`（`field-scene.js:2103,2112`）で**1マス瞬間移動**。`moveTimer`（`STEP_TIME=0.15`）はクールダウンのみで**補間はしていない**。→ カメラが32pxずつカクッと飛ぶ。げんちゃんの「ドラクエみたいに周りがヌルッと動く」要望の本命はこの**歩行補間**。
- 隊列の仲間は `followers[]`（`field-scene.js:1628`）で、移動時に前マスの座標をコピーして追従（`field-scene.js:2093-2101`）。いずれも整数タイル座標。
- セーブは `serialize(gameState)` が **gameState 丸ごと JSON 化**（`src/logic/save.js`）。新フィールドを state に足せば自動でセーブ/ロードに乗る。古いセーブ互換は読み出し側で `state.xxx || {}` で守る。

## 設計方針（全体）

- **既存の当たり判定・エンカウント・ワープ・隊列ロジックは一切変更しない。** 追加はすべて「描画の上乗せ」か「読み取り専用データの参照」に留める。
- バンドル鉄則①（全 src が1スコープに連結）を厳守。**新規トップレベル識別子は衝突回避**（接尾辞や関数内クロージャに閉じ込め）。トップレベルは `var` のみ。
- 各機能はタスク単位で分割し、**タスクごとに実機（`http://localhost:5599/index.html`）で確認**してからげんちゃんに見せる。
- `build.js` の ORDER は編集しない。新規 src ファイルを作る場合のみ ORDER 末尾追加を検討（原則 field-scene.js / menu-scene.js への追記で完結させ、新規ファイルは避ける）。

## 機能① 🎥 スムーズスクロール（歩行のヌルッと補間）

### 目的
1マス移動を数フレームかけて滑らせ、カメラ（周りのマップ）を滑らかに流す。ドラクエ感の本命。

### 実装方針
- `px/py`（整数タイル）は**当たり判定・エンカウント・ワープ用にそのまま維持**。
- 描画専用に「移動アニメ状態」を追加：
  - `moveFromX, moveFromY`（移動開始マス）、`moveProg`（0→1）。
  - 移動確定時（現在 `px = nx` の箇所）に `moveFromX = 旧px; moveFromY = 旧py; moveProg = 0` をセットし、`px/py` は従来通り即座に目標マスへ。
  - `update(dt)` で `moveProg += dt / STEP_TIME`（1.0 で頭打ち）。
  - **表示座標** `renderX = lerp(moveFromX, px, ease(moveProg))`、`renderY` 同様。`ease` は軽い easeOut（例 `t*(2-t)`）で足元が気持ちよくなる程度。
- **カメラ**を `renderX/renderY` 基準に変更：`offX = clampCamera(round(VW/2 - (renderX*TS + TS/2)), VW, mapW)`（Y も同様）。`clampCamera` 自体は無改造。
- **隊列（followers）**：各 follower に `fromX/fromY` を持たせ、リーダーと同じ `moveProg` で lerp 描画。追従ロジック（前マスコピー）は不変。
- 純粋関数として `lerp(a,b,t)` と `stepEase(t)` を切り出し、`node --test` で境界（t=0→a, t=1→b, 単調増加）を検証。

### 壊さない工夫
- 補間はあくまで**表示座標のみ**。ゲームロジックは整数マスで動くので、当たり判定ズレ・すり抜けは発生しない。
- ワープ（マップ切替）時は `moveProg=1`（補間なし）で即描画し、切替演出と競合させない。

### 受け入れ基準
- 歩くとユイトは画面中央付近に留まり、周りのマップが滑らかにスクロールする。
- 隊列4人も滑らかに続く。壁ドン・エンカウント・宝箱・ワープは従来通り動く。

## 機能② 🧭 ミニマップ（画面すみに常時）

### 目的
「今このマップのどこにいて、出口はどっちか」を一目で分かるようにする。

### 実装方針
- `field-scene.js` の `draw` の**最終段**でオーバーレイ描画（既存描画に非干渉）。
- 位置：画面**右上**、角丸半透明パネル（例 78×78px 程度、マップ縦横比に合わせて内接）。
- 内容：
  - 地形は**粗く**：歩ける床＝薄色、壁/水など通れない＝濃色の点。1タイル≒1〜2px。
  - **自分＝光る点**（点滅 or 明色）。
  - **出口（exits）＝小さな矢印/マーカー**。
  - **隠し要素は出さない**：隠し通路（H）・隠し扉・宝箱は地形の「壁/床」区分に丸め込み、探索の楽しみを守る。
- 暗闇マップ（`ambient:'dark'`）でも、自分と出口だけは描く（迷子防止優先）。
- 判定用に「タイルが歩けるか」は既存 `isWalkable` 系ロジックを読み取り専用で流用。
- 大きいマップ（village1 22×20 等）もパネル内に収まるよう縮尺自動計算。

### 壊さない工夫
- 描画のみ。ゲーム状態は読むだけ。パフォーマンスは可視パネルが小さいので軽量。

### 受け入れ基準
- 全マップでミニマップが右上に出て、自分と出口の位置が分かる。隠し通路は露出しない。

## 機能③ 🩧 行き先看板（迷子防止）

### 目的
出口に近づいたとき「この先どこへ行くか」を明示し、迷いをなくす。

### 実装方針
- 各マップの `exits[]` は既に `{x,y,to,tx,ty,msg?}` を持つ。プレイヤーが**出口マスの1〜2マス以内**に来たら、画面**下部**に案内バー「→ ○○のまちへ」を自動表示。
- 行き先名は `exit.to` のマップを引いて `map.name` から**自動生成**（例 to:'town1' → 「ハーバータウン」）。語尾は行き先種別で自然化（町→「〜へ」）。マップ大量編集はしない。
- 近接判定は純粋関数 `nearestExitLabel(map, px, py, radius, mapsById)` として切り出し、`node --test` で「範囲内で最寄り出口名を返す／範囲外は null」を検証。
- 出口から離れたらバーを消す。

### 壊さない工夫
- 表示のみ。exits データは読むだけで書き換えない。

### 受け入れ基準
- 出口に近づくと行き先名バーが出て、離れると消える。行き先名が実マップ名と一致する。

## 機能④ 🗺️ 世界地図画面（メニューから）

### 目的
冒険の全体像と現在地を1画面で把握できるようにする。

### 実装方針
- メニュー（`menu-scene.js`）に項目**「せかいちず」**を追加。開くと専用オーバーレイ/サブモードで全体マップを描画。
- **世界地図レイアウトデータ**を新規定義（読み取り専用の静的データ）：主要ノードのみを2D座標で配置。
  - ノード＝**町・フィールド・ダンジョン入口**（例 field1, town1, field2… village1, cave1入口, tower_ice入口, shrine_forest入口, cave_water入口, ch2_gate, ch2_town, ch2_pass, ch2_castle）。
  - **ダンジョン内の各階（〜2f/3f 等）は個別ノードにせず、入口1ノードに集約**してシンプルに。
  - ノード間の主要な繋がりを線で描く（`exits` の主要接続を反映）。
- **訪問記録** `state.visited{マップキー:true}`：マップ移動確定時に `state.visited[map.id]=true`。古いセーブは `state.visited || {}` で初期化。
  - 未訪問ノードは**モヤ（?表示 or 暗色）**で隠す＝冒険のワクワクを残す。
  - 現在地は**光点**で強調。
- レイアウトデータのノード集約・visited判定は純粋関数化し `node --test` で検証（訪問済みだけ可視・現在地フラグ）。

### 壊さない工夫
- レイアウトは静的データ、visited は state への追記のみ。既存マップ/exits に非干渉。

### 受け入れ基準
- メニュー「せかいちず」で全体図が出る。行った所だけ見え、現在地が光る。未訪問はモヤ。

## 機能⑤ ✈️ ファストトラベル（世界地図からワープ）

### 目的
行ったことがある町へすばやく戻れるようにして、往復のダルさをなくす。

### 実装方針
- 世界地図画面で、**訪問済みの「町」ノードを選択→確認→その町の入口座標へワープ**。
- 対象は**町のみ**（安全地帯）：ハーバータウン(town1)/フォレストタウン(town2)/クラウドタウン(town3)/みのりの村(village1)/ノルドタウン(ch2_town)。フィールド・ダンジョンは対象外（進行・物語ゲートを壊さない）。
- 各町の「到着座標（入口付近の安全マス）」を世界地図レイアウトデータに `warp:{x,y}` として持たせる。
- 未訪問の町は選べない（グレーアウト）。
- ワープ実行は既存のマップ切替処理（position 差し替え＋fieldシーン再生成）を流用。効果音は既存 SE を鳴らす。

### 壊さない工夫
- 町のみ対象なので、ボス前ゲートやストーリーフラグに影響しない。
- ワープ先座標は安全マス固定。既存の遷移機構を再利用し独自遷移を作らない。

### 受け入れ基準
- 世界地図から訪問済みの町を選ぶとワープする。未訪問町は選べない。ワープ後も進行・セーブが正常。

## タスク分割と実装順（一段ずつ実機で見せる）

1. **①スムーズスクロール**（体感が一番変わる。lerp/ease 純関数＋テスト → 表示補間 → カメラ → 隊列 → 実機）
2. **②ミニマップ**（draw 末尾オーバーレイ → 実機）
3. **③行き先看板**（nearestExitLabel 純関数＋テスト → 近接表示 → 実機）
4. **④世界地図画面**（レイアウトデータ → state.visited 記録 → メニュー項目 → 描画 → 実機）
5. **⑤ファストトラベル**（世界地図に warp 座標 → 町選択→ワープ → 実機）

各タスク完了時: `node build.js` → `wc -c` / `md5 -q` → `node --test`（全PASS）→ 実機で目視 → げんちゃんに見せる。

## テスト方針

- 純粋ロジック（lerp/stepEase, nearestExitLabel, 世界地図ノード集約/visited判定）は `node --test` でユニットテスト。
- 描画系（補間表示・ミニマップ・看板バー・世界地図・ワープ）は built index.html を実ブラウザで目視検証（`preview` ツール、server名 srpg-dev）。
- 全タスクで既存テストの回帰ゼロを確認。

## リスクと対策

- **バンドル衝突（黒画面）**：新規トップレベル識別子は接尾辞 or クロージャに閉じ込め。`node --test` はスコープ分離で衝突を検知できないため、必ず built index.html を実ブラウザでロード確認。
- **セーブ互換**：`state.visited` 未定義の旧セーブは読み出し側で `|| {}`。SAVE_VERSION は据え置き（後方互換のため強制はしない）。
- **補間とワープの競合**：マップ切替時は `moveProg=1` 即描画で回避。
- **大きいマップのミニマップ縮尺**：縦横比に内接する縮尺を自動計算。

## 非目標（YAGNI）

- 27マップを1枚の連続マップに物理統合すること（物語ゲート崩壊・作り直しコスト大のためやらない。→ 世界地図＋ファストトラベルで体験だけ実現）。
- ダンジョン各階を世界地図に個別表示すること（入口1ノードに集約）。
- ファストトラベルのフィールド/ダンジョン対応（安全地帯の町のみ）。
